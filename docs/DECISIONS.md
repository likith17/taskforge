# Decision log

Significant, contested decisions get a full record in [ADR/](ADR/). Smaller
ones are listed here with their reason.

## Architecture decision records

| # | Decision | Status |
|---|---|---|
| [0001](ADR/0001-postgresql-as-the-queue.md) | PostgreSQL table as the queue; no Redis | accepted |
| [0002](ADR/0002-polling-vs-notifications.md) | Polling first; `LISTEN/NOTIFY` only if measurements justify it | accepted for M1 |

## Smaller decisions

| Decision | Reason |
|---|---|
| Runtime-checked SQL (`sqlx::query_as`) instead of the compile-time `query!` macros | The macros need a live database or a committed offline cache at build time. Every statement is instead exercised by integration tests against real PostgreSQL. Revisit if query count grows. |
| `#[sqlx::test]` for integration tests | Each test gets its own freshly migrated database, so tests are isolated and run in parallel with no cleanup code. |
| UUIDv7 job ids, generated by the API | Time-ordered ids keep index inserts local and give a stable tiebreak in claim order. Generating in the API means the id exists before the insert (useful for idempotent retries in M2). |
| `state` as `text` + CHECK, not a PostgreSQL enum | Enum changes are awkward to migrate transactionally. |
| `Claim` has crate-private fields | A fencing token that any caller could construct would not be one. Only `claim_next` produces it. |
| `JobSubmission` uses `deny_unknown_fields` | A client sending `max_attempts` or an idempotency field before they exist gets a `422`, not a silently ignored option. |
| Handlers run in a spawned task | A panicking handler fails its job, not the worker loop. |
| No CLI-parsing or dotenv dependency | Four subcommands and a handful of environment variables do not justify them. |
| `chrono` for time | First-class SQLx and Serde support; default features disabled. |
| Relative delays resolved on the database clock | `run_at` is compared with `now()` in the claim query; using the same clock for both removes clock skew between machines as a failure mode. |
| Migration 0001 contains only columns Milestone 1 uses | Unused columns would carry constraints no test exercises. Later milestones add theirs as new migrations. |
| TaskForge lives in `taskforge/` | The repository root already held the Python prototype; nothing of it was modified. |

## Toolchain note

The project builds with the installed stable toolchain, **Rust 1.85** (edition
2024), not the newest stable release. The workspace sets `rust-version = "1.85"`
and uses Cargo's MSRV-aware resolver, so dependency versions are chosen to
compile on that compiler. Updating the toolchain is a one-line change.
